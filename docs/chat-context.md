## Уточнения по первоисточникам

Этот раздел проверен отдельно 25.10.2026 и не является восстановлением старых ответов.

### Slovo: данные и модели

По [README Slovo](https://github.com/hukenovs/slovo#downloads):

| Материал | Отличие |
| --- | --- |
| Slovo, около 16 ГБ | Видео, обрезанные по границам жеста |
| Origin, около 105 ГБ | Исходные видео до обрезки |
| 360p, около 13 ГБ | Уменьшенные исходные видео; минимальная сторона 360 пикселей |
| Landmarks, около 1,2 ГБ | Покадровые ключевые точки рук MediaPipe для обрезанных видео |

Это разные представления данных. Готовые модели — обученные распознаватели,
а не дополнительные наборы примеров. В разделе [Models](https://github.com/hukenovs/slovo#models)
есть веса ONNX и TorchScript; SignFlow вынесен отдельно. Совместимость конкретных
весов с координатами Holistic нужно проверить по входному формату.

В `annotations.csv` есть класс `text`, идентификатор ролика `attachment_id`,
участник `user_id`, флаг разделения `train`, границы `begin`/`end` для исходных видео.
Готовые Landmarks описаны как точки рук: наличие позы и лица из этого не следует.

### MediaPipe Holistic

[Официальное описание Holistic Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/holistic_landmarker)
описывает извлечение точек лица, тела и обеих кистей из изображений, видео и потока камеры.
Для определения слова РЖЯ поверх этих признаков нужен распознаватель жестов.
При реализации следует закрепить версию и конкретный API MediaPipe: нельзя
предполагать совпадение старого Holistic и актуального Holistic Landmarker.

## Предлагаемые архитектурные варианты

Следующие варианты сформулированы при сохранении контекста. Выбор пользователем
между ними не подтверждён.

### A. Последовательности ключевых точек

Обучение: видео Slovo → Holistic → последовательности признаков → временная модель
(кандидаты: LSTM/GRU, TCN или Transformer) → класс жеста.

Работа приложения: камера → тот же Holistic и предобработка → буфер кадров →
обученная временная модель → оценка уверенности → текст.

Нужно одинаково обрабатывать обучающие видео и камеру: порядок точек, координаты,
нормализацию масштаба и положения, левую/правую руку, пропуски обнаружения,
частоту кадров и длину окна. Хранить маску отсутствующих точек. Если нужны поза
и лицо, извлечь их из видео; готовый архив точек рук их не заменяет.

### B. Готовая видеомодель

Камера → подготовка видеоклипа под вход выбранных весов → видеомодель → класс → текст.
Holistic можно использовать для визуализации или вспомогательной обработки.
Если модель принимает RGB-кадры, координаты точек нельзя подставить вместо них;
это требует другой модели или её переобучения.

### C. Расширение после первого прототипа

Сравнить распознавание по точкам и по видео, затем при необходимости объединить
их оценки. Непрерывный поток потребует выделения границ жестов и обработки пауз.
Перевод связной речи РЖЯ в грамматические русские предложения — отдельный этап.

## Предлагаемый следующий шаг

1. Уточнить смысл ранее выбранного «уровня 2» и выбрать архитектуру первого прототипа.
2. Определить небольшой словарь жестов и способ запуска распознавания:
   запись отдельного жеста или непрерывный поток.
3. Проверить один ролик Slovo и один пример с камеры через выбранный MediaPipe.
4. Проверить формат данных и выбранных весов; только затем выбирать обучение
   своего классификатора либо готовую модель.
5. Оценивать качество на людях, не использованных для обучения; сохранять
   разделение Slovo и выделять валидацию внутри обучающей части по `user_id`.
6. Предусмотреть состояние «жест не распознан», паузы и подавление повторного вывода.

## Что ещё не согласовано

Конкретный словарь, модель и веса, версии библиотек, интерфейс, оборудование,
целевые точность и задержка, необходимость распознавания дактиля, непрерывной
речи и формирования предложений. Конспект не подтверждает, что эти функции уже реализованы.
