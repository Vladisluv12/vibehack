# Spec: работа моделей с Second Brain по уровням (weak / frontier)

Статус: proposed (25.10.2026). База кода — `Vladisluv12/vibehack`, ветка `second-brain`,
коммит `a598515` (команда поверх `71e9efe`). Ветку `origin/translator` не сливать:
её diff удаляет 33 файла Second Brain.

## Goal

Модели, работающие с Second Brain, должны со временем решать задачи лучше и дешевле,
а хранилище — не засоряться. Самоулучшение (рефлексия, авто-навыки) включается только
для слабых моделей. Для frontier — проверка, курация, качественная выдача и запись по
правилу. Каждый механизм включён для уровня, только пока измерение показывает пользу.

## Current state

- Markdown-хранилище, frontmatter `id/type/review/source/source_hash`, SQLite FTS5,
  связи `[[id]]`, stdlib Python. MCP: `search_knowledge`, `get_document`,
  `get_related`, `create_draft` (всегда `proposed`). `reviewed` ставит только человек.
- Команда добавила GitHub-импорт (`second_brain/github.py`), новый graph UI,
  Windows-совместимое ядро. 15/17 Python-тестов проходят, 2 web-теста требуют сокет.
- Нет: журнала мутаций, lint, телеметрии, дедупа черновиков, оценки эффективности.
- Найденные дефекты (аудит Sol, проверено вручную):
  - **F3** `mcp_server.py:create_draft` вызывает `create(..., links=source_ids)` без
    `declared_only`: wiki-ссылки и `- contradicts [[..]]` из текста черновика попадают
    в канонический граф. Черновик агента не должен менять граф до ревью.
  - **F1** `github.py:import_repo` строит URL источников по имени ветки, не по SHA
    коммита: провенанс не воспроизводим.
  - **F2** повторный импорт не обновляет проект (key = URL репо), нет связи версий.

## Required behavior

### R0. Уровень модели задаёт хост, а не модель

- Файл вне vault `--state/agents.json`: `{"models": {"<model-id>": "weak"|"frontier"},
  "default": "frontier"}`. MCP-сервер запускается с `--agent-model <id>`; уровень
  берётся из файла. Модель не может объявить себе уровень через инструмент.
- Неизвестная модель → `frontier` (безопасный дефолт: меньше автоматических записей).
- Каждая запись от агента несёт `agent_model` и `agent_tier` во frontmatter и журнале.

### R1. Общее для обоих уровней (фундамент)

1. **Declared-only черновики (фикс F3).** `create_draft` создаёт заметку с
   `declared_only=true`; предложенные связи хранятся как `proposed_links` в
   frontmatter и в граф не попадают, пока человек не примет запись.
2. **Журнал мутаций (S7).** Каждая операция `create/edit/import/restore`:
   JSONL-запись `op_id, ts, actor, agent_model, tier, op, note_id, sha256_before,
   sha256_after, reason`, сначала intent, потом commit (crash-safe). Журнал — барьер:
   если запись intent не удалась, мутация не выполняется. Пакетный откат по `actor`
   или `op_id`. Хранится в state, не в пересоздаваемом индексе.
3. **Lint (S4), только детерминированный, CLI `lint`.** Мёртвые `[[id]]`, сироты
   (кандидаты, не ошибки), дубли ID, пустой `source` у `proposed`, формат
   `source_hash`, отсутствие обязательных полей записи опыта. Читает полный индекс
   (не 500 узлов графа, не первые 100 warnings). Проверка URL по сети — отдельный
   флаг `--online`, по умолчанию выключена.
4. **Точный дедуп (S3).** Fingerprint = sha256 нормализованных `title + body +
   sorted(source_ids)` (без frontmatter). Повтор возвращает существующий id и
   `dedup: true`. Существующий `reviewed` никогда не перезаписывается.
5. **Шлюз записи.** Черновик опыта (`type: experience|skill`) без `source_ids`,
   `applies_to` (область применимости) и `evidence` (как проверено) отклоняется с
   понятной ошибкой. Ошибку видит модель и может исправить запрос.
6. **Журнал полезности выдачи.** Каждый `search_knowledge/get_document` пишет
   `served(note_id, run_id)`. Новый инструмент `report_usage(run_id, used_ids,
   outcome)` фиксирует, что реально помогло. Служебные чтения (sync, UI-тур) не
   считаются. Это основа для S1: устаревшим считается то, что выдаётся, но не
   помогает, а не то, что редко читают.
7. **Сигнал неполноты.** Ответ `search_knowledge`, обрезанный по лимиту, содержит
   `truncated: true` и общее число совпадений.
8. **Гипотеза ≠ факт в выдаче.** Каждый результат MCP несёт `review` и
   `agent_model` автора; `proposed`/`unreviewed` возвращаются с пометкой
   «не проверено» и ранжируются ниже `reviewed` при равной релевантности.
   Черновик, ссылающийся только на `proposed`-источники, помечается
   `evidence: self-referential` шлюзом R1.5. Защита от самоподкрепления и
   отложенного отравления памяти (reflect-risks: Microsoft, Mem0).

### R2. Измерение эффективности (обязательно до включения R3/R4)

- `evals/tasks/*.json`: 30–50 задач с детерминированным oracle (тест, ожидаемый
  файл, команда с кодом выхода). Хеши задач в `evals/tasks.lock`; заметки, у
  которых `source` ведёт на eval-сессию, выдача исключает (защита от утечки).
- Конфигурации на каждый уровень: **A** — Second Brain как есть (R1);
  **B** — A + проверенные навыки; **C** — B + рефлексия/курация уровня.
- Метрики: `success_first_try`, `cost_per_success` (токены и время),
  `repeated_error_rate` (см. R3.2), число записей в хранилище за прогон.
- Runner `python3 -m second_brain eval --tier weak --config B --model <id>`
  вызывает внешний CLI агента; в тестах — fake-агент, сеть запрещена.
- Решение: механизм остаётся включённым для уровня, если нижняя граница 90%
  bootstrap-интервала прироста `success_first_try` > 0 и `cost_per_success` не
  растёт больше чем на 20%. Иначе флаг выключается, причина пишется в журнал.
  Решение оформляется как `proposed` decision-заметка: включить по нему механизм
  в прод может только человек.

### R3. Слабые модели: самоулучшение

1. **Сбор опыта (E1).** Приёмник событий хуков (Claude Code, Hermes
   `post_tool_call/subagent_stop`, OpenCode) через `Extension.post` или CLI
   `ingest-run`. Белый список полей, `redact.py` до записи, reasoning не хранится.
   Сырые дампы сессий не импортируются.
2. **Триггеры рефлексии (E2), только по событиям:** исправлена ошибка с той же
   сигнатурой, что в прошлом прогоне; пользователь поправил стратегию; выполнена
   процедура из ≥ N шагов с успешным oracle; найдено противоречие с `reviewed`;
   навык, выданный в прогоне, связан с проваленным oracle. Сигнатура ошибки =
   sha256 нормализованного сообщения/stack trace (без путей, чисел, адресов), без LLM.
   Debounce и дедуп событий; события от самого ревизора не триггерят ревизора.
3. **Ревизор (S2).** Отдельный процесс, а не HTTP-handler. Доступ только к
   read-инструментам и `create_draft`. Бюджет токенов на прогон, выключатель.
   Двухстадийный: reflect (что случилось, почему) → consolidate (сверить с
   существующими навыками: ADD / UPDATE-как-новый-черновик-с-`supersedes` / NOOP).
   Пишет `type: skill`, `review: proposed`, с `applies_to`, `evidence`, `run_ids`.
4. **Пакет навыков.** Перед задачей слабая модель получает не более k (по
   умолчанию 3) навыков `reviewed` с совпадающим `applies_to`, в формате
   «индекс + references» (как `/learn` в Hermes), с бюджетом символов.
5. **Канарейка.** Принятый человеком навык сначала выдаётся в 20% прогонов;
   полный выпуск — после сравнения на живых прогонах (метрики R2).
6. **Frontier учит слабых.** Задача, решённая frontier-моделью с успешным
   oracle, может стать черновиком навыка для слабых. Принимается только если
   слабая модель с ним решает лучше, чем без него (R2, конфигурация B).

### R4. Frontier: без авто-рефлексии

1. Правило записи в описании MCP-сервера (одно, короткое): проверь `search`, нет
   ли уже; сохраняй только воспроизводимое знание с источником, областью
   применимости и тем, как проверено; не сохраняй очевидное и одноразовое.
   Шлюз R1.5 делает правило проверяемым.
2. Инструмент `reflect(run_id)` — только по явному запросу модели или человека;
   результат — черновик `proposed`.
3. Предложения связей (S5) — как `proposed_links`, не как канонические связи.
4. `review_at`, прогнозы и Brier (S6) — отложено: включать только если R2 покажет,
   что frontier-модели действуют по ним иначе. (Автор karpathy-llm-wiki счёл
   численную уверенность «ложной точностью» после 3 месяцев эксплуатации.)

## Non-goals

- Дообучение весов, RL, векторная БД, графовая БД.
- Автоматическое повышение до `reviewed` — никогда, ни одним механизмом.
- Подключение Second Brain к Hermes через `skills.external_dirs`: с 07.10.2026
  фоновый review Hermes может править внешние и закреплённые навыки (PR #134432).
  Только MCP.
- Интеграция ветки translator.
- Платные модели и обход лимитов в eval-runner.

## Constraints

- Runtime ядра — stdlib Python 3.11+ (MCP уже требует `fastmcp`, это существующее
  исключение). Новых зависимостей нет.
- Веб слушает только `127.0.0.1`. Ключи и токены не пишутся в журнал, заметки,
  отчёты eval.
- Изменение схемы SQLite → поднять версию схемы и добавить миграцию. Журнал,
  телеметрия, eval-результаты — в отдельных таблицах/файлах state, не в `notes`
  (sync их пересоздаёт).
- Markdown-файлы остаются источником истины; индекс пересоздаваем.

## Implementation considerations

- Точки встраивания (по аудиту, `a598515`): журнал — `brain.py:Brain.create/edit`,
  импорт, `restore_backup`; lint — рядом с `Brain._sync`, отдельный CLI; дедуп и
  шлюз — `mcp_server.py:create_draft` + атомарно под `Brain.lock`; телеметрия —
  границы `mcp_server.py` (не `Brain.get`: его вызывает search для всех результатов).
- F1/F2 (SHA коммита и версии импорта) — до любого stale/review по внешним
  источникам.
- Ревизор и eval-runner — отдельные модули (`second_brain/reviewer.py`,
  `second_brain/evals.py`), провайдер модели передаётся как argv внешнего CLI;
  ядро о провайдерах не знает.
- Готовые проекты как образцы, не зависимости: Mem0 (ADD/UPDATE/NOOP), OpenDream
  (reflect → consolidate), mcp-memory-service (supersede без удаления),
  llm-wiki-compiler и lucasastorian/llmwiki (детерминированный lint), Hermes
  `evals/session_search_schema` (A/B с программными oracle, без LLM-судьи),
  Hermes ledger (before/after sha256 — но у нас журнал обязан быть барьером).

## Acceptance criteria

1. Черновик с `[[x]]` в теле не добавляет ребро в `links`, пока не `reviewed`.
2. Любая мутация видна в журнале с before/after sha256; падение между intent и
   commit восстанавливается при старте; откат по `actor` возвращает файлы.
3. `lint` на showcase-vault выдаёт полный отчёт; на чистом vault — 0 ошибок.
4. Повторный `create_draft` того же содержания возвращает тот же id.
5. Черновик `type: skill` без `applies_to`/`evidence`/`source_ids` отклоняется.
6. Модель не из `agents.json` получает уровень `frontier`; модель не может сменить
   свой уровень.
7. Для `weak` ревизор запускается только по событиям R3.2; для `frontier` — никогда
   сам. Ревизор не может вызвать `edit` или создать `reviewed`.
8. `eval` на fake-агенте считает метрики, bootstrap-интервал и выключает механизм
   без прироста; eval-заметки исключены из выдачи.
9. Все тесты проходят без сети; web по-прежнему только `127.0.0.1`.
