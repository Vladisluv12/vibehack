# Second Brain

Локальная база знаний на Markdown: источник истины — файлы `.md` (открываются в
Obsidian), поиск и граф — пересоздаваемый индекс SQLite FTS5. У каждой записи есть
происхождение (`source`, `source_hash`) и статус проверки:

- `unreviewed` — импортировано, никто не проверял;
- `proposed` — предложено человеком или агентом;
- `reviewed` — проверено человеком. Агент не может выставить этот статус.

Runtime — только стандартная библиотека Python 3.11+. Сеть не нужна (кроме явного импорта
с GitHub). Работает на
Linux, macOS и Windows (на Windows вместо `python3` — `python` или `py`).

## Быстрый старт

```bash
make test          # Python; JS-тесты фронтенда: node --test tests/*.mjs
make demo          # копирует examples/demo-vault (8 заметок) в var/ и открывает панель
make showcase      # то же для examples/showcase-vault: 80 связанных заметок для презентаций
```

Панель: http://127.0.0.1:8765/ (слушает только localhost, API защищён токеном страницы).

## CLI

```bash
python3 -m second_brain --vault PATH --state PATH sync
python3 -m second_brain --vault PATH search 'запрос'
python3 -m second_brain --vault PATH read <id>
python3 -m second_brain --vault PATH import file.md --split   # внешний источник → unreviewed
python3 -m second_brain --vault PATH import-github https://github.com/owner/repo
python3 -m second_brain --vault PATH backup
python3 -m second_brain restore backup.zip new-empty-dir
python3 -m second_brain --vault PATH serve --port 8765
python3 -m second_brain --vault PATH mcp                       # нужен пакет fastmcp
```

`--vault` и `--state` можно задать через `SECOND_BRAIN_VAULT` / `SECOND_BRAIN_STATE`.
State (индекс, резервные копии) держите вне vault.

## Теги

Три способа, все совместимы с Obsidian:

```markdown
---
tags: ["поиск", "project/alpha"]   # или YAML-списком: tags: и строки «  - поиск»
---
Текст с инлайн-тегом #идея.
```

В панели — поле «Теги» при создании заметки или правка Markdown. Теги нормализуются
(регистр, `#` в начале), чисто цифровые (`#123`), якоря ссылок и теги в коде не считаются;
в импортированном внешнем тексте учитываются только теги из frontmatter. Поиск `#тег`
фильтрует по тегу и подсвечивает заметки на графе; популярные теги — в «Ваши знания».
API: `notes?tag=…`, `tags?space=…`.

## Пространства: люди и агенты

Заметки делятся на два пространства. Агентские — с `source: "agent:…"` (так помечает
черновики MCP-шлюз) или с явным `space: "agent"` во frontmatter; остальные — человеческие
(`space: "human"` тоже можно указать явно). В панели переключатель «Люди / Агенты / Всё»
показывает отдельные графы: агенты пишут много коротких связанных заметок, и их граф не
должен заслонять содержательные заметки людей. API: `?space=human|agent` у `notes` и `graph`.

## Смысловые связи и эмбеддинги

Кнопка ⚙ — настройки. Источник векторов: встроенный (без сети: TF-IDF по словам и
символьным n-граммам, лексическое сходство) или эндпоинт — OpenAI-совместимый
(`POST {url}/embeddings`: OpenAI, LM Studio, vLLM, LiteLLM, llama.cpp), Ollama
(`/api/embed`) или HuggingFace TEI (`/embed`). Для русского рекомендуем `bge-m3` или
`USER-bge-m3` (без префикса); для multilingual-e5 — префикс `query: `. Настройки и ключ
лежат в state (`settings.json`, 0600); ключ панели не возвращается.

Как считается (идеи из Basic Memory, Smart Connections, Obsidian Copilot, Khoj — код не
заимствован): текст очищается от строк связей, `[[id]]` заменяется названием; заметка режется
по заголовкам на фрагменты ~1000 символов с префиксом «название > H1 > H2», плюс «головной»
вектор (название + первые 900 символов). Сходство пары = 0.5·cos(голов) + 0.5·среднее
лучших совпадений фрагментов в обе стороны. Предлагаются только взаимные ближайшие соседи
(k=10, не больше 5 на заметку) выше порога; порог «авто» = max(пол модели, 98-й перцентиль
сходства по базе). Уже связанные и скрытые пары исключаются, пары выше 0.95 помечаются как
возможные дубли. Векторы кэшируются в `state/semantic.sqlite` по хешу модели и текста
фрагмента — при правках запрашиваются только изменившиеся фрагменты.

На графе предложения — пунктир («≈ Смысловые»); в карточке заметки — «Похоже по смыслу» с
похожими фрагментами и кнопками «Связать» (дописывает `- relates_to [[id]]` в Markdown,
с сохранением версии) и «Скрыть». По умолчанию ищутся связи между заметками людей.

## Поиск: BM25, по смыслу, гибрид

BM25 (FTS5) остаётся режимом по умолчанию. Плашка в строке поиска и переключатель в
выпадающем списке дают ещё два режима, выбор сохраняется в настройках:

- **По смыслу** — вектор запроса (с «Префиксом запроса» из настроек) сравнивается с
  головным вектором и фрагментами заметок, используются те же кэшированные векторы, что и
  для смысловых связей. Находит «резервное копирование» → «Бэкап с манифестом».
  Со встроенным провайдером это нечёткий лексический поиск (словоформы, опечатки).
- **Гибрид** — reciprocal rank fusion (k=60) выдачи BM25 по любому из слов и смыслового
  поиска.

`#тег` всегда фильтрует по тегу. API: `GET /api/brain/search?q=…&mode=bm25|semantic|hybrid&space=…`.

## Чат с LLM

Зелёная кнопка «Спросить базу» справа внизу. Вопрос → поиск заметок (по смыслу, если
подключены эмбеддинги, иначе гибрид) → ответ модели только по ним со ссылками `[n]`;
ссылки кликабельны, под ответом — процитированные источники со статусом проверки.
Заметки передаются модели как пронумерованные данные с явным указанием не выполнять
инструкции из них; непроверенные сведения модель должна помечать. «Сохранить как
черновик» создаёт заметку `proposed` в пространстве агентов (`source: agent:chat`) со
связями на процитированные заметки.

Настройки ⚙ → «Чат с LLM»: Ollama (`/api/chat`, `think: false`) или OpenAI-совместимый
сервер (`/chat/completions`), модель, ключ, число заметок в контексте. Проверено с
`qwen3:1.7b` и `bge-m3` в Ollama:

```bash
docker run -d --name sb-ollama -p 127.0.0.1:11434:11434 -v sb-ollama:/root/.ollama ollama/ollama:0.40.2
docker exec sb-ollama ollama pull bge-m3
docker exec sb-ollama ollama pull qwen3:1.7b
```

## Импорт с GitHub

Кнопка «GitHub» в панели или `import-github URL` в CLI. Скачивается архив ветки по
умолчанию; в памяти читаются только `.md`-файлы (без скрытых папок, `node_modules`,
`vendor`; до 200 файлов и 20 МБ текста, архив до 50 МБ), на диск ничего не распаковывается.
Репозиторий становится заметкой-проектом, каждый файл — источником `unreviewed` со ссылкой
на GitHub и связью с проектом, поэтому на графе появляется отдельный кластер. Вики-ссылки
внутри импортированного текста связями не становятся. Повторный импорт неизменённых файлов
дубликатов не создаёт. Приватные репозитории — через переменную окружения `GITHUB_TOKEN`.

## MCP для агентов

`mcp` поднимает STDIO-шлюз с четырьмя инструментами: `search_knowledge`,
`get_document`, `get_related`, `create_draft`. Удаления, правки существующих заметок
и повышение статуса через него недоступны; черновики агента всегда `proposed`.

## Плагины (Agent Control)

GUI целиком входит в этот пакет. Блоки агентов (лента вызовов, метрики проекта,
страница «Очередь агентов») заполняет необязательное расширение — подкласс
`second_brain.web.Extension`, переданный в `make_server(..., extension=...)`.
Без расширения панель пишет «Agent Control не подключён», а `/api/extension`
возвращает `{"connected": false}`. Само хранилище об агентах ничего не знает.

```python
class MyAgents(Extension):
    name = 'Agent Control'
    pages = {'/queue': '<html>…</html>'}        # доп. страницы, __CONTROL_TOKEN__ подставится
    def get(self, path, params, open_brain): ... # None → 404
    def post(self, path, data, open_brain): ...  # (status, body) или None
```

## Фронтенд

`second_brain/static/` — готовая сборка панели (force-graph на canvas, ~200 КБ): граф на весь
экран, кластеры (label propagation с затравкой по проектам) с цветом и свечением, дуги связей,
подписи по важности узла. Поверх графа: KPI, поиск по заметкам (Ctrl K; совпадения
подсвечиваются на графе), выдвижной каталог «Ваши знания» с фильтрами по типу и статусу проверки и созданием заметки, инспектор с Markdown и кликабельными `[[ссылками]]`, режимы
«Кластеры/Типы» и «Весь граф/Окружение 1–2 шага», «Демо-тур» по ключевым узлам. Заливка
узла — статус проверки: сплошная — reviewed, полупрозрачная — proposed, пустая — unreviewed.

`examples/showcase-vault` — синтетическая база вымышленной команды; пересобирается
`python examples/build_showcase.py`. Исходники панели в `frontend/`; пересборка требует сети:
`pnpm install && pnpm run build` (версии закреплены в `pnpm-lock.yaml`, пакеты моложе
14 дней не ставятся; сборка воспроизводится побайтно и заново пишет
`THIRD_PARTY_NOTICES.md` по реально вошедшим в бандл пакетам).

## Происхождение

Модуль выделен из локального проекта agent-control (оркестратор агентов). Здесь
хранилище, индекс, вся панель и MCP-шлюз; очередь задач, воркеры и импорты
истории агентов остаются в agent-control, который подключается как расширение.
